# roles

Roles, coordinator modes and VM notes for agents on an exe.dev VM, set up by
pointing Shelley at this repo:

```
Set up github.com/dan-stowell/roles on this VM, following its README.
```

Add "in research mode" for the research coordinator.

## For Shelley: setting this up

1. Clone this repo to `~/roles` (or `git -C ~/roles pull` if it's there).
2. Run `~/roles/setup`, adding `--mode research` if you were asked for
   research mode. It's safe to rerun.
3. Tell the user, in a few lines:
   - the login page URL it prints, for logging claude in from a phone;
   - that Shelley starts normal conversations with **Default**; choose
     **Multi-agent** explicitly to coordinate these roles;
   - that a Shelley model change it reports takes effect once Shelley
     restarts (`sudo systemctl restart shelley`), which ends this
     conversation, so leave that to the user;
   - any warnings it printed, such as missing git identity.

Don't edit the installed copies in `~/.claude` or `~/.config`; change this
repo and rerun `setup`.

## Shelley's opt-in profile

`setup` creates or updates one native **Multi-agent** profile and selects the
built-in **Default** as the startup default, without editing its settings.
**Assistant** stays Shelley's separate built-in messaging/personal-assistant
profile, not the normal coding startup default.

Multi-agent combines Shelley's stock system-prompt template with
`modes/build.md` and `modes/shelley.md`. It always uses build coordination;
`setup --mode research` changes Claude's mode only. Native nonempty templates
replace the stock prompt, so this is a copied base: rerun after Shelley
upgrades to refresh it. Reruns preserve Multi-agent's other profile settings.
Choose Multi-agent in Shelley's profile selector when you want delegation;
existing conversations are not switched to it.

On an already set-up VM, refresh just the profile and `~/.claude/agents` with:

```sh
~/roles/install-shelley-profile
```

This needs Python 3, curl, and a running Shelley exposing
`~/.config/shelley/shelley.sock`. It uses the documented local Unix-socket
API, not TCP (which requires authentication), and does not restart services.
For a fresh VM, use full `setup` to install guidance and the other tools too.
The installer removes only the exact global coordinator hook generated by
older `setup` versions, and only after successful profile/default saves.
It refuses unknown or symlinked `system-prompt` hooks before changing anything:
review and move those aside yourself, since they would affect all profiles.

## What's here

- `guidance.md`: the VM notes every agent reads. Everything builds with tools
  on the VM, following each repo's own docs.
- `roles/`: helper roles, as claude subagents. `implementer`, `verifier`,
  `adversary` and `ideator`.
- `modes/`: what the main agent does with them. `build` plans, implements,
  verifies and opens draft PRs; `research` generates and probes research
  paths and writes them up. `shelley.md` is how Shelley maps the roles onto
  its subagents.
- `login/`: a page at `https://VMNAME.exe.xyz:8001/` that starts
  `claude auth login`, shows the sign-in link to copy, and takes the code
  back. Set `ROLES_LOGIN_ALLOW` to a comma-separated email list before
  running `setup` to restrict it further than exe.dev's proxy does.

## Development checks

Run from the repo root:

```sh
bash -n setup
shellcheck setup
python3 -m unittest discover -s tests -v
```

In `login/`, run:

```sh
go test -race ./...
go build ./...
go vet ./...
```
